### What is an API?
API = Application Programming Interface
- It's a tool that allows programmers to use external functions and features independent of the developers program
- Exists in Several forms:
	- Third Party Libraries (Java, .NET, C++ libraries) that can be referenced
	- Exposed using the web - Web API / Web Service

#### Web Services
Interoperable Endpoints accessible over the web
- Client agnostic

Typically two flavors:
- SOAP – Simple Object Access Protocol
	- Strict Rules enforced by an XML schema
	- Transfer data over XML
	- Support several transport protocols (HTTP, SMTP TCP …)

- REST – Representational State Transfer
	- No strict data structures
	- Transfer data using JSON, XML, Form Data
	- Uses HTTP protocol

### REST
Client
- The person or software who uses the API
- Ex: You use GitHub API to create a program to read and update your profile.
- The client can also be a web browser.
- Ex: When you go to GitHub website, your browser is the client who calls GitHub API and uses the returned data to render information on the screen.

Resource
- It can be any object the API can provide information about.
- Each resource has a unique identifier. The identifier can be a name or a number.
- Ex: Instagram’s API, a resource can be a user, a photo, a hashtag

*REST Message Structure*
```
POST /api/2.2/auth/signin HTTP/1.1
HOST: my-server
Content-Type:application/json
Accept:application/json

{
  "credentials": {
    "name": "administrator",
    "password": "passw0rd",
    "site": {
      "contentUrl": ""
    }
  }
}
```

#### How this Involves HTTP
- Most average web applications use GET and POST.  GET to retrieve values and POST to update or create new values. POST is used in submitting web forms.  
- The REST architecture pattern gives PUT and DELETE proper usage and treats POST as an update function and PUT as a creation function.
- This allows us to start making CRUD like web pages.
