### Client-Side Development
Code is executed on the clients computer (The user in their browser)
- The Client makes a request for a web page
	- HTML File
	- CSS Files
	- JavaScript files
	- Images
- The only language available for client-side is JavaScript

*How Requests are made and client-side JavaScript Code works*
![[jsServerSide2.0-1.png| Diagram from slide 4]]

Code that enhances user experience
- Handle user events
- Validate user input
- DOM manipulation
- Animations
- Store local data
- Drag and Drop
- Theme and personalize
- Fetch data

#### What Client Side Development Can't Do
- Connect to Databases
- Read and Write files to disk
- Make data retrieval requests to other servers without special server setup (CORS)
- Cannot handle security for login and authentication
	- User Passed
- Send Emails and Notifications
- Run Background tasks
- Handle heavy computations
- Protect Company intellectual property
	- Client-side code can be read by users as it is downloaded locally and can easily be viewed in a browser. 

*This is When we need server side code*

### What Is Server-Side Code?
- Code that resides on a server and is executed by the server. It can never be downloaded by the client.
- Handles client requests and sends the client responses 
- Generate Sever-Side Dynamic HTML
- Connect to databases and to other servers
- Handles application security and payment transactions
- Handles real-time application communications like chat, collaboration, network-based gaming
- Logging of events and errors
- Handle millions of simultaneous requests
- Intellectual Property is protected
- Wide range of language or languages to choose from
- Background tasks, AI, heavy computations
- Scale resources when required for handling even greater load and demand
- Create web services for client agnostic integrations

#### Node.js and Web Servers
- Node.js is Commonly used as a web server to serve web applications, JSON, REST APIs and more
- Using the Node.js core HTTP module, we can spawn a web server and serve a web application

*Example of a Simple Server*
```JavaScript
const http = require('http'); // Import the HTTP module

// Create a Web Server Object
var server = http.createServer((request, response) => {
	response.writeHead(200, {"Content-Type": "text/plain" });
	response.end("Hellow World\n");
});

// Have the Server listen for incoming requests on Port 4000
server.listen(4000);
console.log("Node.js Server is Running at port 4000");
```
- Add 200 status code to the response back to the client ( refer back to [[02. HTTP]] from MVC, 200 = OK )

*Example of different pages and url mapping*
```JavaScript
var http = require('http');
const port = 3000;

var server = http.createServer((req, res) => {
	let now = new Date();
	
	// Check the URL of the current request
	if (req.url == '/') {
		res.writeHead(200, {'ContentType-': 'text/html' });
		res.write('<html><body>');
		res.write('<div><a href="/">Home</a><a href="/">Courses</a></div>');
		res.write('<p>This is the Home page.</p><p>Created ${now}</p>');
		res.write('</body></html>');
		res.end();
	}
	else if (req.url == '/courses') {
		res.writeHead(200, {'ContentType-': 'text/html' });
		res.write('<html><body>');
		res.write('<div><a href="/">Home</a><a href="/">Courses</a></div>');
		res.write('<p>This is the Courses Page.</p><p>Created ${now}</p>');
		res.write('</body></html>');
		res.end();
	}
	else {
		res.end('Invalid Request');
	}
});

server.listen(port);
console.long("Server Is running at port 3000");
```
