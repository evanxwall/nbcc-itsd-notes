### Static Vs. Dynamic Websites

#### How Web Servers Process Static Websites
- A browser requests a page from a web server by sending an HTTP request. 
- For a Static web page, the HTTP request includes the mane of the HTML file that is being requested. 
- The web server replies to the request by sending an HTTP response back to the browser
- For a Static web page, the HTTP response is the HTML document.

![[javaEEDiagram.png|Diagram from slide 6 of Java - Class 04 - JSP and Servlet]]

#### How Web Servers Process Dynamic Websites 
- A Dynamic website is and HTML document that is **generated** by the web application.
- Web server gets a request for a dynamic web page, the server passes the request to the web application. The application generates the response (usually an HTML document), and returns it to the web server.
- The web server wraps the generated HTML document in an HTTP response and sends it back to the browser. The browser doesn't care if it's a static or dynamic HTML document that was generated by the web application. 

![[javaEEDiagram2.png | Diagram from slide 7 of Java - Class 04 - JSP and Servlets]]

#### How Web Servers Process Dynamic Websites with a Database
- Most times, web applications need a way to save and retrieve data for display and modification. A **persistence** mechanism is required to save this data.
- Data can be saved in relational databases, or using other systems like NoSQL
- The application can retrieve and write to the database.
- Sometimes it can Create, Update, Read, and Delete (CRUD) data from the database.
- It can execute business rules, do computations, and transform the data that is served to web clients.

- Java web applications consist of **Java / Jakarta Server Pages (JSPs)** and **Servlets.** 
- Also can contain static HTML, CSS and JavaScript files

### Java Web Architecture and MVC
*This stuff is pretty much the same as [[01. Introduction to ASP.Net MVC]] in terms of MVC*.

**View:** It's the presentation layer for a Java web application, typically consists of HTML pages and JSPs.
	- Try and keep business logic out of the View layer. 

**Controller:** The business logic / rules layer for a Java web application. Consists of Servlets. Servlets may use other Java Classes like 'filters,' or 'services,' or other utilities

**Model:** The Data Access layer for a Java Web App consists of classes that read and write data that is stored on the server's disk drive and / or in a Database. 
	- For a serious web app, the data is usually stored in a relational or non-relational database
	- data may also be stored in binary files, text files, or XML files
	- The Model layer should also contain Java Classes to represent each "entity" in the database. 
	- All data and business logic code should be test-able using a console app

### HTTP Methods
When working with webservers, we use different HTTP methods:
- use GET when:
	- The request reads data from the server
	- The request can be executed multiple times without causing problems

- use POST when:
	- The request writes to the server
	- You do now want to expose parameters in the URL for security reasons
	- You do not want parameters included when bookmarking a page
	- You need to transfer large amounts of data ( > 4KB )

- use PUT to replace or update resource at the given URL
	- it can return codes 200 or 201
	- It can be cached
	- Idempotent
		 *An HTTP method is **idempotent** if the intended effect on the server of making a single request is the same as the effect of making several identical requests*

- use DELETE when:
	- You want to delete a resource
	- It can return codes 200, 202, 204

### Request a JSP with HTTP GET
- You make a request to a JSP page in the browser URL
	 http://localhost/MyJSPPage.jsp
- Supply parameters to the server using query string appended in the page URL
	 http://localhost/MyJSPPage.jsp?name=Jimmy%20Jones
	- The ? is the start of the query string parameters
	- Query string parameters are key value pairs. Key is the parameter name and the value is the value of the parameter. Key and value are separated with the = sign. 
	 \<parmname>=\<parmvalue> ( firstname=Jimmy )
- the & separates multiple query string parameters 
	- firstname=jimmy&lastname=Jones.
- \<a> and \<img> are examples of tags that use HTTP GET

Examples:

Two form tags that use HTTP GET
```HTML
<form action="display_email_entry.jsp">
<form action="display_email.entry.jsp" method="get>
```

Obtain query string parameters in Java code
```Java
String paramValue = request.getParameter("<nameofquerystringparam>");

// So http://localhost:8080/ThirdJSP/display_email_entry.jsp?email=jim@nbcc.ca
// would return

String email = request.getParameter("email"); // Returns jim@nbcc.ca
```

### Send to a JSP with HTTP POST
- Add `method="post` to a form tag
- Parameters are not visible for security
- Parameters are obtained using the request.getParameter() method
- Forms can POST to:
	- Themself
	- Another JSP page
	- Servlet

Examples

Form tags that use POST
```HTML
	<form action="display_email_entry.jsp" method="post">
		<input type="text" name="email" />
		<input type="Submit" value="Add Email" />
	</form>
```

Obtain it in Java
```Java
String paramValue = request.getParameter("<nameOfTheHTMLcontrol>");

// So getting the email would be:
String email = request.getParameter("email");

```

#### JSP Directives
- To define the conditions that the JSP engine should follow when converting a JSP into a Servlet, you can use a JSP Directive. 
- To Import classes in a JSP, you use the import attribute of the page directive. This makes the imported classes available to entire page.
- You can use page directives to define other conditions like error handling. 


*JSP Directives That import Java Classes*
```JSP
<%@ page import="business.*, data.*, java.util.Date" %>  
<%  
    // get parameters from the request  
    String firstName = request.getParameter("firstName");  
    String lastName = request.getParameter("lastName");  
    String emailAddress = request.getParameter("emailAddress");

    // get a relative file name    ServletContext sc = this.getServletContext();  
    String path = sc.getRealPath("/WEB-INF/EmailList.txt");

    // use regular Java objects  
    User user = new User(firstName, lastName, emailAddress);
    UserIO.add(user, path);  
%>  
<p>  
    This email address was added to our list on <%= new Date() %>  
</p>
```

#### JSP Comments
- When you code HTML comments, the comments are complied and executed, but the browser doesn't display them. 
- When you code JSP comments, the comments are not complied or executed. 
- When you code Java comments within a scriptlet, the comments are not complied or executed either. 

*An HTML Comment in JSP*
```HTML
<p>
	<!--
		<%= new Date() %>
	-->
</p>
```

*A JSP comment*
```JSP
<%--
	<p>This Email address was added you our list on <%= new Date() %></p>
--%>
```

*Java Comments in a JSP Scriptlet*
```JSP
<%
    // get parameters from the request
    String firstName = request.getParameter("firstName");
    String lastName = request.getParameter("lastName");
    String emailAddress = request.getParameter("emailAddress");

    /*
	    User user = new User(firstName, lastName, emailAddress);
	    UserIO.add(user, path);
    */
%>
```

#### JSP Declarations
- You can use JSP declarations to declare instance variables and methods.
- Since instance variables are not thread-safe, two threads may conflict when they try to read, modify, and update the same instance variable at the same time. 
- In general, you should avoid coding instance variables for JSPs and Servlets. Instead, you should use other thread-safe techniques for working with global variables. 
- Same goes for methods, you should avoid coding methods within JSPs. Try to use some combination of JSPs, Servlets, and regular Java classes. 

*JSP Code that declares and Instance Variables*
```JSP
<%-- import any packages needed by the page --%>
<%@ 
	page import="business.*, data.*, java.util.Date, java.io.*" 
	// Import our Classes
%>
<%!
	// declare an instance variable for the page
    int globalCount = 0;  // this is not thread-safe
%>
```

*JSP Code that Declares a Method*
```JSP
<%!
    // declare a method for the page
    public void add(User user, String filename) throws IOException {
        PrintWriter out = new PrintWriter(new FileWriter(filename, true));
        out.println(user.getEmailAddress()+ "|"
        + user.getFirstName() + "|"
        + user.getLastName());  
        out.close();
    }
%>
```

- Both of these examples can be done but should be avoided.

### What is a Servlet?
- A Servlet is a Java class that extends the HTTP Servlet class and runs on the server within a server container. 
- Typically, the name of the Servlet begins with a verb to identify the task it performs.
	 Ex: CoolServlet, AwesomeServlet
- It has no constructors, just a `init()` method. 
- Servlets are complied before they are deployed unlike JSPs that compile that Servlet at the first call. 
- Servlets can operate differently for data sent via a GET vs. a POST method.
- Most business logic is placed in Servlets. 

#### Structure of a Servlet
- All Servlets extend the HTTPServlet class. The Servlet must import the `java.io, jakarta.servlet, and jakarta.servlet.http` packages. 
- The doGet methods overrides the doGet method OF the HTTPServlet class and processes all HTTP requests that use the GET method. 
- The doPost methods overrides the doPost method OF the HTTPServlet class and processes all HTTP requests that use the POST method. 
- The doGet() and doPost() methods use two objects that are passed to it by the web server: 
	- The `HttpServletRequest` object, or the request object.
	- The `HttpServletResponse` object, or the response object.
- The `setContentType()` method of the response object sets the content type of the response that will be returned by the browser. 
- The `getWriter()` method of the response object returns a `PrintWriter` object that can be used to send HTML to the browser. The content type must be set before you can create a PrintWriter object. 

*Structure for a simple Servlet that returns HTML*
```Java
import java.io.*;
Import jakarta.servlet.*;
Import jakarta.servlet.http.*;
// Importing the Needed Packages

public class SampleServlet extends HttpServlet 
// Extends the right Class w/ Naming Conventions
{
    @Override       // Overriding the default HttpServlet doPost() function
    public void doPost(HttpServletRequest request, HttpServletResponse response) throws IOException, ServletException 
    {
        //business processing
        response.setContentType("text/html");
        // Sets the ContentType before getting PrintWriter Object
        
        PrintWriter out = response.getWriter();
        out.println("<h1>HTML from servlet</h1>");
        out.close();
    }

     @Override       // Overriding the default HttpServlet goGet() function
     public void doGet(HttpServletRequest request, HttpServletResponse response)throws IOException, ServletException 
     {
        doPost(request, response);
     }
}
```


*Structure for a simple servlet that returns JSON*
```Java
import java.io.*;
Import jakarta.servlet.*;
Import jakarta.servlet.http.*;

public class SampleServlet extends HttpServlet
{  
    @Override
    public void doPost(HttpServletRequest request, HttpServletResponse response) throws IOException, ServletException 
    {
        //business processing
        response.setContentType(“application/json");
        PrintWriter out = response.getWriter();
        out.println(“{ firstName : ‘Brett’, lastName : ‘Lund’ }");
        out.close();
    }

     @Override  
     public void doGet(HttpServletRequest request, HttpServletResponse response)throws IOException, ServletException 
     {
        doPost(request, response);
     }
}
```

### Mapping Servlets
- Before you can request a Servlet, you must map the Servlet to a URL in the `web.xml` file that is in your project.
- The mapping statements are written within the web-app element in `web.xml`
- Mapping Statements Include:
	- Servlet Name
	- Servlet Class
	- Servlet URL
	- Configuration settings like session timeouts, welcome files list, etc...\
- Servlet names are usually the same as the class name. 

*Servlet Mapping Example*
```XML
<?xml version="1.0" encoding="UTF-8"?>
<web-app xmlns="https://jakarta.ee/xml/ns/jakartaee"
         xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
         xsi:schemaLocation="https://jakarta.ee/xml/ns/jakartaee
         https://jakarta.ee/xml/ns/jakartaee/web-app_6_1.xsd"
         version="6.1">

    <!-- Register the servlet -->
    <servlet>
        <servlet-name>QuizServlet</servlet-name>
        <!-- You pick the name, should resemble the Servlet -->
        
        <servlet-class>servlet.QuizServlet</servlet-class>
        <!-- The Fully Qualified Class name, including it's package -->
    </servlet>

    <!-- Map the servlet to a URL -->
    <servlet-mapping>
        <servlet-name>QuizServlet</servlet-name>
        <!-- Looks for the Servlet we just registered. -->
        
        <url-pattern>/quiz</url-pattern>
        <!-- Defines the URL that will trigger the Servlet -->
    </servlet-mapping>
</web-app>
```
