### What is Hashing?
- One-way Function: Converts input to fixed-size output (Hash)
- Same input is always the same Hash
- Cannot be reversed
- Used for passwords storage and data integrity

### What is Salting?
- A random string added to a password before hashing
- Helps to prevent attackers from using precomputed tables (nbownbow tables)
- Each uses gets a unique salt
- Stored along side the hashed password
- same passwords will result in different hashes
- Ex: hash( password + salt )

### What is Encryption?
- It is Reversible. It can be encrypted then decrypted with a key.
- Symmetric Encryption: same key for encrypting and decrypting (AES).
- Asymmetric Encryption: public/private key pairs (RSA).
- Used for secure communication, not for password storage.
- Ex: Cipher cipher = Cipher.getInstance("AES");

### Sorting a Password (Creating an Account)

```Java
private final BCryptPasswordEncoder encoder = new BCryptPasswordEncoder();
BCryptPasswordEncoder();

// When Creating a New User
String rawPassword = 'nbcc2026';
String hashedPassword = encoder.encode(rawPassword); // Adds Salt to the Password

user.setUsername("Chad Thaddington");
user.setPassword(hashedPassword); 

// Save user to DB (via Entity Manager)
em.persist(user);

// The raw password is salted and hashed before entering the DB
// No plaintext passwords in the database. 
```

### Verifying a Password (Login)

```Java
Query q = em.createQuery(
	"SELECT u FROM UserInfo u WHERE u.username = :username");
	
q.setParameter("username", username);
UserInfo user = (UserInfo) q.getSingleResult();

// Compare Raw and Hashed Passwords
if (encoder.matches(rawPassword, user.getPassword()))
{
	return user;
}
else
{
	return null; 
}
```

### Key Points

- `encoder.encode()`: Hashes and Salts automatically
- `encoder.matches(raw, hash)`: Compares entered password with stored password
- BCrypt is adaptative. it can be configured to take more time as hardware gets faster
- Never do a query with `WHERE username = ? AND password = ?`.  It's dangerous and Insecure
